# Lab1. Factory (порождающий)

## Цель
Отделить создание объектов от их использования.

## Как работает паттерн
Проблема: если в коде клиента написать `new CloudModel()`, то клиент жёстко привязан
к конкретному классу — поменять модель на другую значит переписывать клиент.

Решение: клиент работает только с общим интерфейсом, а создание конкретного
объекта выносится в отдельное место — фабрику. Клиент вызывает
`ChatModelFactory.Create("cloud")` и получает объект, не зная его класса.
Выбор класса по строке живёт в одном месте — в фабрике.

## Как реализовано
| Класс | Роль |
|-------|------|
| `IChatModel` | общий интерфейс: метод `Answer(string)` |
| `CloudModel` | продукт 1: медленный платный ответ |
| `LocalModel` | продукт 2: быстрый бесплатный ответ |
| `MockModel` | продукт 3: мгновенная заглушка для тестов |
| `ChatModelFactory` | фабрика: по строке `"cloud"/"local"/"mock"` создаёт нужный класс |
| `Program` (верх) | клиент: берёт модель у фабрики и общается только с интерфейсом |

Смысл: если завтра добавится четвёртая модель, клиентский код менять не нужно —
добавится класс и один `if` в фабрике.
