# Lab11. Visitor (поведенческий)

## Цель
Отделить алгоритмы от структуры объектов: новые операции без правки существующих классов.

## Как работает паттерн
Проблема: есть набор классов (элементы), и нужно выполнять над ними разные
операции (печать, подсчёт, экспорт...). Если писать операцию методом внутри
каждого класса, то каждая новая операция = правка всех классов.

Решение: операция выносится в отдельный класс-визитор. Каждый элемент имеет
метод `Accept(visitor)`, который просто вызывает `visitor.VisitЭтотТип(this)`.
Элементы знают только интерфейс визитора; добавить новую операцию = написать
новый класс-визитор, существующий код не трогаем.

## Как реализовано
| Класс | Роль |
|-------|------|
| `IChatElement` | интерфейс элемента: метод `Accept()` |
| `UserMessage`, `AssistantMessage` | два конкретных элемента (реплика пользователя / ответ модели с токенами) |
| `IChatElementVisitor` | интерфейс визитора: по методу `Visit...` на каждый тип элемента |
| `VisitorPrint` | визитор-операция 1: печатает диалог |
| `VisitorCost` | визитор-операция 2: суммирует токены и считает стоимость |

В демо: один и тот же список диалога прогоняется через оба визитора —
элементы при этом не изменились ни на строчку.
