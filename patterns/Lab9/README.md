# Lab9. Lazy инициализация (порождающий/поведенческий)

## Цель
Оптимизация ресурсоёмких операций: создание откладывается до последнего момента
и выполняется ровно один раз.

## Как работает паттерн
Вместо объекта хранится фабрика (`Func<T>`) и флаг «создано». Первый `Get()`
вызывает фабрику и запоминает результат, все последующие — отдают готовое.
Потокобезопасность — double-checked locking: быстрая проверка без блокировки,
затем под `lock` повторная проверка (пока один поток был в локе, другой мог
уже создать значение).

## Как реализовано
| Сущность | Роль |
|----------|------|
| `MyLazy<T>` | обобщённый контейнер: два конструктора (фабрика / готовое значение), `Get()`, `Value`, `IsValueCreated`, `ToString()` |
| `NeuralModel`, `EmbeddingIndex` | «дорогие» объекты: долгие конструкторы + статические счётчики загрузок |
| `Program` | 4 сценария |

Полезные детали реализации:
- исключение в фабрике не кешируется: `_created` остаётся `false`,
  следующий `Get()` пробует снова;
- конструктор с готовым значением — когда лень не нужна, значение уже есть;
- `ToString()` не провоцирует создание (в отличие от `Value`).

## Демо
1. `IsValueCreated == False` сразу после создания; первый `Value` грузит модель,
   второй возвращает тот же объект (`ReferenceEquals == True`), загрузка 1 раз.
2. Готовое значение создаётся уже «созданным».
3. Фабрика бросила исключение — значение не закешировалось.
4. Гонка: 8 потоков через `Barrier` одновременно зовут `Get()` —
   счётчик сборок индекса равен 1, двойная проверка работает.
