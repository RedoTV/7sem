# Паттерны проектирования — чётные лабораторные (C#)

Единый сюжет всех лаб: платформа для работы с LLM («нейронкой») — биллинг токенов,
шлюз запросов, каталог моделей, генерация текста.

| № | Папка | Паттерн / тема | Что внутри |
|---|-------|----------------|------------|
| 2  | `Lab2`  | Singleton (потокобезопасный) | Биллинг токенов: 8 потоков-сессий пишут в единый реестр. Два способа: double-checked locking (`TokenLedger`) и `Lazy<T>` (`ModelCatalog`). В конце сверка: ни один токен не потерян. |
| 4  | `Lab4`  | Композиция vs наследование | ИИ-ассистент, собранный из сменных модулей: «мозг» (`IReasoner`), память (`IMemory`), навыки (`ISkill`), форматтер. Горячая замена модулей на лету; анти-пример — комбинаторный взрыв классов при наследовании. |
| 6  | `Lab6`  | Decorator | Обвязка LLM-клиента матрёшкой: Budget → Throttle → Cache → Retry → Logging → ядро. Видно кэш-попадание, спасение от сетевого сбоя и пробитие дневного лимита токенов. |
| 8  | `Lab8`  | Strategy | Сэмплирование следующего токена при генерации: greedy / temperature / top-k / top-p над марковской цепочкой. Один seed — разные результаты только из-за подмены стратегии. |
| 10 | `Lab10` | Chain of Responsibility | Публичный шлюз LLM-API: лог → авторизация → модерация → лимит длины → квота → модель. Второй конвейер (админский канал) собран без модерации и квот. |
| 12 | `Lab12` | Specification | Каталог LLM-моделей: подбор по критериям (цена, контекст, латентность, модальности) через комбинируемые спецификации And / Or / Not + автоподбор лучшей модели через LINQ. |

## Запуск

Нужен .NET SDK (проверено на .NET 10). Из корня репозитория:

```
dotnet run --project Lab2
dotnet run --project Lab4
dotnet run --project Lab6
dotnet run --project Lab8
dotnet run --project Lab10
dotnet run --project Lab12
```

Каждая лаба — самостоятельный консольный проект: один `Program.cs` с комментариями
по паттерну + `.csproj`.
