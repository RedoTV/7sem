# Лаба 5. Proxy (структурный паттерн)

## Задание
Реализовать прокси для «удалённого сервиса»: метод запроса данных с задержкой,
прокси кеширует результат.

## Тематика
Удалённый сервис — облачный LLM. Каждый поход в сеть: задержка 0.7–1.4 с
и деньги за токены. `CachingLlmProxy` подставляется вместо настоящего сервиса
и кеширует ответы.

## Что показывает паттерн
- подмена объекта обёрткой: клиент работает с `ILlmService` и не знает,
  говорит ли он с прокси (`RemoteLlmService` и `CachingLlmProxy` взаимозаменяемы);
- дополнительная логика ДО вызова настоящего объекта: проверка кеша,
  TTL, статистика попаданий;
- ключ кеша — хеш(model + prompt + temperature): тот же вопрос с другой
  temperature даёт промах;
- экономия реальных вызовов: 4 запроса → 3 похода в сеть (2-й отвечен из кеша).

## Запуск
```bash
dotnet run --project Lab5
```

## Структура
- `LlmService.cs` — интерфейс `ILlmService` и RealSubject `RemoteLlmService`;
- `CachingLlmProxy.cs` — Proxy: кеш с TTL, счётчики hit/miss;
- `Program.cs` — сценарий демонстрации HIT/MISS/TTL.
