# Lab7. Observer (поведенческий, C++, обобщённый)

## Цель
Слабая связанность: издатель оповещает подписчиков, не зная их классов.

## Как работает паттерн
Издатель (Subject) хранит список подписчиков (Observer) и при изменении
состояния рассылает им событие. Подписчики реализуют общий интерфейс,
поэтому добавлять/убирать их можно в любой момент. Возможна и обратная связь:
подписчик может вызвать метод издателя и повлиять на его поведение.

Обобщённость: каркас сделан шаблоном `Subject<TEvent>` / `Observer<TEvent>` —
один и тот же код работает с любым типом события (C++-аналог generic-классов).

## Как реализовано
| Сущность | Роль |
|----------|------|
| `Observer<TEvent>` | абстрактный подписчик: чисто виртуальный `update()` |
| `Subject<TEvent>` | издатель: `attach()`, `detach()`, `notify()`, `std::vector<Observer<TEvent>*>` |
| `EpochEvent`, `PriceEvent` | два разных типа событий |
| `TrainingRun : Subject<EpochEvent>` | издатель №1: обучение нейросети, `stop()` для обратной связи |
| `MetricsLogger`, `EarlyStopping` | подписчики №1: журнал и остановка на плато (вызывает `run.stop()`) |
| `MarketFeed : Subject<PriceEvent>` | издатель №2: доказывает переиспользование каркаса |
| `AlertBot` | подписчик №2: алерт при превышении цены |

Владелец подписчиков — `main`, издатель хранит не владеющие указатели
(`Observer<TEvent>*`): он знает только интерфейс, не классы.

## Демо
1. Обучение: loss падает до 5-й эпохи, потом плато. EarlyStopping считает эпохи
   без улучшений и на 8-й останавливает обучение через `run.stop()` —
   подписчик влияет на издателя.
2. Котировки: тот же шаблонный каркас, событие `PriceEvent`; после `detach`
   алерт больше не приходит.
