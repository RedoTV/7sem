# Lab7. Observer (поведенческий, C++)

## Цель
Показать слабую связанность: издатель и подписчики почти ничего не знают друг о друге.

## Как работает паттерн
Проблема: при изменении состояния объекта нужно оповестить другие объекты.
Если издатель напрямую вызовет их методы, он жёстко привяжется к их классам,
и добавить нового подписчика будет нельзя без правки издателя.

Решение: подписчики реализуют общий интерфейс `Observer` с одним методом
`update()`. Издатель хранит просто список указателей на этот интерфейс.
Когда состояние меняется — пробегает по списку и вызывает `update()` у всех.
Добавить/убрать подписчика можно в любой момент через `attach()`/`detach()`.

## Как реализовано
| Класс | Роль |
|-------|------|
| `Observer` | абстрактный интерфейс подписчика: чисто виртуальный `update(double loss)` |
| `Training` | издатель: `std::vector<Observer*>`, методы `attach()`, `detach()`, `notify()`, `run()` |
| `Logger` | подписчик 1: логирует каждую эпоху |
| `Checkpoint` | подписчик 2: реагирует только когда loss стал лучшим |

В демо: обучение 6 эпох с двумя подписчиками, затем логгер отписывается
(`detach`) и обучение продолжается — издатель при этом никак не менялся.
Тематика — обучение нейросети: издатель сообщает loss после каждой эпохи.
